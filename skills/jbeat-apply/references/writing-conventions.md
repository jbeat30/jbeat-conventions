# Writing Conventions

Applies to authored documentation, README text, source comments, review and issue
comments, commit subjects and bodies, PR titles and bodies, and explanations and
progress reports. See [language-conventions.md](language-conventions.md) for language
and [project-rule-resolution.md](project-rule-resolution.md) for conflicting rules.
Do not rewrite unrelated existing prose merely to normalize style.

- Do not use the middle dot (`·`) as an authored prose separator. Use commas,
  conjunctions, or separate sentences.
- Avoid hyphens and dashes (`-`, `–`, `—`) as decorative separators or parenthetical
  interruptions. Use ordinary sentences unless required by language or meaning.
- Preserve required syntax and exact text: Markdown lists and table delimiters,
  code, identifiers, paths, URLs, command flags, versions, negative numbers,
  standard notation, necessary spelling, and verbatim quotations or contracts.
  Exceptions do not authorize decorative separators in surrounding prose.
- Prefer concrete outcomes and reasons. Expand only when evidence, constraints,
  or a decision needs explanation.

Example: write `타입, 린트, 빌드 확인` without joining terms with a middle dot. Keep
`--help`, `jbeat-apply`, and Markdown list markers intact.
